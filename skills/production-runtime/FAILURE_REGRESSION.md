# Production Runtime Failure Regression Gates

These failures must remain testable and must not silently recur:

1. literal-but-wrong-intent → Mission Compiler + confidence-aware dual track.
2. 1,000 near-duplicates → concept-family diversity quotas.
3. beauty over correctness → correctness/mission fit rank first.
4. maker judges own work → independent verifier gate.
5. content lost to fit → required-content manifest hard gate.
6. Thai/Unicode/font failure → font-ready, glyph coverage, overflow checks.
7. renderer crash stops whole job → declared deterministic fallback ladder.
8. silent quality downgrade → fallback fidelity disclosure gate.
9. fake Thai narration → Thai TTS fail-closed adapter.
10. full rebuild for tiny change → dependency hash + incremental rebuild.
11. prompt injection from web/source → external text treated as untrusted data.
12. preference overreach → scoped preference/confidence/exception model.
13. autonomy before QC → no release before QC + verification.
14. rule bloat → small core + lazy-loaded runtimes.
15. no measurement → telemetry + canary + shadow benchmark.

A regression gate is stronger than a memory note: once a failure is encoded here, a replacement runtime should demonstrate how it prevents or detects it before promotion.
